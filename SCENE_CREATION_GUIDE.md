# Scene Creation Guide

How to create a new scene for COV from scratch. This guide assumes no prior knowledge of the codebase. Follow the sections in order.

---

## 1. Concepts

A scene is a room the player can enter. Each scene consists of:

- A **background image** and optional foreground/midground layers
- A **darkmap** texture that drives ambient shadow on characters and things
- A **Godot scene file** (`.tscn`) that wires everything together
- A **JSON script file** (`.json`) that defines exits, interactions, and event sequences
- Optionally, a **C# script** (`.cs`) if the scene needs procedural logic beyond what JSON supports

The player character navigates within a **NavigationRegion2D** polygon. Interactive objects are **things**. Room edges are **exit zones** (CollisionShape2D nodes).

---

## 2. Directory Structure

Every scene lives in its own subdirectory. Scene-specific art lives alongside the scene files:

```
game/
  scenes/
    yourscene/
      yourscene.tscn          ← Godot scene file
      yourscene.json          ← JSON script (auto-discovered alongside .tscn)
      yourscene.cs            ← C# script (optional; only if JSON is insufficient)
      yourscene.cs.uid        ← auto-generated by Godot
      yourscene_bg.png        ← background image
      yourscene_bg.png.import ← auto-generated by Godot on first import
      yourscene_dm.png        ← darkmap
      yourscene_dm.png.import
      yourscene_fg.png        ← foreground layer (optional)
      yourscene_mg.png        ← midground layer (optional)
      somesprite.png          ← any other scene-specific art (thing sprites, etc.)
      somesprite.png.import
  art/
    light.png                 ← shared PointLight2D texture used by all scenes
    items.png                 ← inventory item sprites (used by MainScene UI)
    cursors2.png              ← cursor sprite sheet (used by MainScene UI)
    (other shared/UI assets)
```

Scene-specific art (backgrounds, darkmaps, thing sprites) goes in the scene's own directory. Shared assets used across multiple scenes or by the UI stay in `game/art/`.

---

## 3. Art Assets

All art for a scene goes in the scene's own directory (`game/scenes/yourscene/`). Drop files there before importing them in the Godot editor.

### Background image

- **Dimensions:** 1440×930 px (high-resolution) or 640×480 px (standard resolution)
- **Format:** PNG, opaque
- File name convention: `{scenename}_bg.png`
- The sprite is placed at `(720, 465)` (center of a 1440×930 canvas) or `(320, 240)` for 640×480 art. This centers it relative to the scene's coordinate origin.

### Darkmap

- **Same dimensions as the background image**
- **Format:** PNG, greyscale (or colour — only luminance is sampled)
- Brighter areas = brighter (more illuminated). The engine samples this texture at each thing's and the character's base position each frame and adjusts the character/thing shader's `overall_dark` parameter accordingly.
- Paint the darkmap in your image editor: pure white = fully lit, pure black = fully dark, gradients for transitions.
- File name convention: `{scenename}_dm.png`

### Foreground / midground layers (optional)

- Same dimensions as the background
- Rendered on top of (fg) or behind (mg) the character using `z_index`
- Foreground objects that the character can walk behind
- Listed in the scene node's `parallaxSprites` export array for a subtle parallax scroll effect as the camera pans

### Thing sprites

- Place in the scene directory alongside the `.tscn`
- Can be individual PNGs or sprite sheets
- Sprite sheets: set `hframes` / `vframes` on the `Sprite2D` child of the thing node
- No fixed dimension requirement — size them to match the scene scale
- If the thing is animated, it needs an `AnimationPlayer` sibling node

### Shared assets (do not copy per-scene)

`game/art/light.png` is the `PointLight2D` texture used by every scene — reference it from `game/art/` directly. UI assets (`items.png`, `cursors2.png`, etc.) also stay in `game/art/`.

## 4. Setting Up the Scene in the Godot Editor

### 4.1 Create the scene file

1. In the Godot FileSystem panel, navigate to `game/scenes/`.
2. Right-click → **New Folder** → `yourscene`
3. Inside that folder, create a new scene: **Scene → New Scene**
4. Set the root node type to **Node2D**
5. Rename the root node to match your scene name exactly, e.g. `yourscene` (lowercase, no spaces)
6. Save as `game/scenes/yourscene/yourscene.tscn`

### 4.2 Attach the scene script

1. Select the root node
2. In the Inspector, click the **Script** property → attach `res://framework/scene_script.cs`
3. Set the exported properties:
   - **displayName**: the short identifier for this scene, e.g. `"yourscene"`. Must match the key you will add to `GameData.Scenes` (see §7).
   - **darkMap**: drag in `game/scenes/yourscene/yourscene_dm.png`
   - **parallaxSprites**: add any foreground/midground sprite nodes (after creating them)
   - **entryScriptFile**: leave blank — the JSON is auto-discovered from the .tscn path

### 4.3 Add the background sprite

1. Add a child **Sprite2D** node, name it `background`
2. Set **Texture** to `game/art/yourscene_bg.png`
3. Set **Position** to `(720, 465)` for 1440×930 art, or `(320, 240)` for 640×480
4. Set `z_as_relative = false`, `z_index = 0` (so it stays behind everything)

### 4.4 Add a Camera2D

1. Add a child **Camera2D** node
2. Position it somewhere reasonable (e.g. near the scene centre)
3. The framework controls it at runtime — leave `Enabled = false`; `scene_script._EnterTree()` manages this

### 4.5 Add a CameraClamp (optional but recommended)

If the scene is larger than the viewport (640×480), add a **CollisionShape2D** named exactly `CameraClamp`:

1. Add a child **CollisionShape2D**, name it `CameraClamp`
2. Set **Shape** to a **RectangleShape2D**
3. Size it to cover the full walkable area of the scene (e.g. `1437×928` for a full 1440×930 background)
4. Position it at the centre of the background, e.g. `(718, 465)`

The camera will clamp to this rectangle so it never shows outside the background.

### 4.6 Add a PointLight2D

Used for shadow direction calculations. Required if any thing has `castsShadow = true`.

1. Add a child **PointLight2D**
2. Set **Texture** to `game/art/light.png`
3. Adjust **Position** to simulate the light source direction (high and to one side for a strong directional shadow)
4. Set **Height** (controls shadow length — larger = longer shadows)
5. Set **Energy** as needed for the visual look

### 4.7 Add the NavigationRegion2D

This defines where the character can walk.

1. Add a child **NavigationRegion2D**, leave its name as `NavigationRegion2D`
2. In the Inspector, create a new **NavigationPolygon** resource
3. Draw the walkable polygon in the editor viewport by clicking to place vertices. The polygon must be convex or decomposed into convex sub-polygons (Godot handles this automatically from outlines). Trace the ground surface where the character can walk — include depth variation (near the bottom of the screen the polygon is lower/wider, near the top it narrows).
4. The polygon is defined in scene-local space. Coordinates are relative to the scene root.

**Important:** The polygon must not have holes or self-intersections. If you need to exclude an area (e.g. a table), cut the polygon around it.

### 4.8 Add the ScalerStick

The scale system uses a **Line2D** node named `ScalerStick` with exactly **3 points** to define depth zones. Objects higher in the scene (further away) are scaled smaller.

1. Add a child **Line2D**, name it `ScalerStick`
2. In the Inspector under **Points**, add exactly 3 points:
   - Point 0: somewhere in the far background (top-left area), e.g. `(-500, -300)`
   - Point 1: the midpoint of the scene depth
   - Point 2: somewhere in the near foreground (bottom-right area), e.g. `(500, 400)`
3. Adjust the 3 points so the line passes from top-left to bottom-right through the scene's depth axis. The character's scale interpolates along this stick based on Y position.
4. Set **Width** to something visible for debugging (e.g. `4.0`); it is invisible at runtime.

### 4.9 Add exit zones

Each exit is a **CollisionShape2D** node whose name starts with `exit_to_`. The node name must match the key used in the JSON `exits` section.

1. Add a **CollisionShape2D** child
2. Name it `exit_to_{destinationscenename}`, e.g. `exit_to_kitchen`
3. Set **Shape** to a **RectangleShape2D**
4. Size and position it at the edge of the scene where the character walks out
5. The character's placement on arrival (in the destination scene) will be centered on this shape's position. Size it to cover the doorway or walkable transition area.

Exit zones must use **RectangleShape2D** — other shape types are ignored by the framework.

### 4.10 Add a FreezeScaleRegion (optional)

In areas where perspective scaling should be disabled (e.g. a doorway, a porch step where depth is ambiguous), add a **CollisionPolygon2D** named `FreezeScaleRegion`. Objects inside this polygon keep their scale constant.

1. Add a **CollisionPolygon2D**, name it `FreezeScaleRegion`
2. Draw a polygon around the area where scale should be frozen
3. No other configuration needed — the framework auto-detects it by name

### 4.11 Add the Character

1. Add an **instance** of `game/character/ego.tscn` as a child
2. Name it `ego` (exact name required — the framework finds it by this name)
3. Set **Position** to a default starting position in the scene (will be overridden on scene entry by arrival data)
4. Adjust **character_speed** if this scene warrants different movement speed (default: 85.0)
5. Set `modulate` to a dark colour matching other scenes if the character should appear pre-shaded (e.g. `Color(0.17, 0.17, 0.17, 1)` for the current art style)

### 4.12 Add midground and foreground sprites (optional)

For parallax layers:

1. Add **Sprite2D** children named `mg` (midground) and/or `fg` (foreground)
2. Set their textures to the appropriate art files
3. Set `z_as_relative = false`; foreground should have a positive `z_index` (e.g. 5), midground a lower one
4. After creating them, add them to the root node's **parallaxSprites** export array in the Inspector

## 5. Adding Things (Interactive Objects)

A **thing** is any object the player can click on — a door, a prop, an NPC, a pick-up item.

### 5.1 Create a thing node

1. Add a child **Node2D** to the scene root
2. In the Inspector, attach a script. For a purely JSON-driven thing, attach `res://framework/thing.cs` directly. For a thing that needs custom C# logic, create a script that extends `thing`:
   ```csharp
   public partial class yourthing : thing
   {
       public override void _Ready()
       {
           base._Ready();
           // optional custom setup
       }
   }
   ```
3. Name the node to match how you will refer to it in JSON (lowercase, no spaces), e.g. `door`, `axe`, `oldlamp`

### 5.2 Set exported properties

In the Inspector (with the thing node selected):

| Property | Description |
|---|---|
| `displayName` | Human-readable name shown in the verb tray (e.g. `"OLD LAMP"`) |
| `castsShadow` | `true` if this object should cast a drop shadow |
| `inventoryItemType` | Set to the matching `InventoryItem.ItemType` value if this thing can be picked up; otherwise `none` |
| `lookClosely` | `true` to zoom in when the player looks at it |
| `lookText` | Array of strings — fallback look responses if no `look` interaction is defined in JSON |
| `interactionFile` | Leave blank — interactions are defined in the scene JSON |
| `startingScaleAsBaseline` | `true` (default) — the thing's initial scale is treated as its baseline for depth scaling |
| `isScaleFrozen` | `true` to disable depth scaling for this object regardless of position |

### 5.3 Add child nodes to the thing

A typical thing node has these children (all optional depending on what the thing needs):

**Sprite2D** (named `Sprite` or anything — the framework finds it by type):
- Set **Texture** to the art asset
- Set `hframes` / `vframes` for sprite sheets
- Set **Frame** to the default frame

**AnimationPlayer** (if animated):
- Create animations that drive the Sprite2D frame
- Animation names are referenced in JSON with `play_animation`

**CollisionPolygon2D** (click area — required for player to click on it):
- Name it anything; the framework finds it by type
- Draw a polygon that covers the visible part of the sprite
- This is purely for click detection, not physics

### 5.4 Set interactPoint, centerPoint, basePoint

These are Vector2 properties set at runtime by the framework based on the click polygon. However, you can manually nudge `interactPoint` (the position the character walks to when interacting) by adding a **Marker2D** child named `InteractPoint`. If present, the framework uses it; otherwise it defaults to the center of the click polygon.

### 5.5 Depth ordering

Things are sorted by their Y position at runtime. Ensure each thing's **Position** Y coordinate reflects its perceived depth in the scene (closer to the bottom of the screen = in front of things higher up).

## 6. The JSON Script

Each scene has a `.json` file co-located with its `.tscn`. This file defines:

- **exits**: where each exit zone leads and what happens when the character arrives there
- **things**: interaction responses for each interactive object
- **default**: reserved for future scene-level defaults (currently unused; include as `{}`)

The file is auto-discovered: the framework replaces `.tscn` with `.json` in the scene file path.

### 6.1 File structure

```json
{
  "exits": { ... },
  "things": { ... },
  "default": {}
}
```

### 6.2 Exits

Each key in `"exits"` must exactly match a `CollisionShape2D` node name in the `.tscn`.

```json
"exits": {
  "exit_to_kitchen": {
    "destination": "kitchen",
    "arrive_dir": "down"
  }
}
```

**Fields:**

| Field | Required | Description |
|---|---|---|
| `destination` | Yes | Short scene name (must match a key in `GameData.Scenes._byName`), e.g. `"kitchen"` |
| `arrive_dir` | Yes | Direction the character faces and walks on arrival: `"up"`, `"down"`, `"left"`, `"right"` |
| `arrive_area` | No | Name of the exit zone in the *destination* scene where the character should be placed. Only needed when the destination scene has no exit pointing back to this scene (i.e. the reverse connection doesn't exist). The framework auto-detects the arrival zone by looking for an exit in the destination whose `destination` matches this scene's `displayName`. |
| `no_walk` | No | `true` to suppress the auto-walk-out-of-zone movement on arrival. Useful for scenes where the character should not move after entering. |
| `arrive_sequence` | No | Array of event actions to run on arrival instead of the auto-walk. Implies `no_walk`. See §6.4. |

**Example with `arrive_sequence`:**

```json
"exit_to_entryway": {
  "destination": "entryway",
  "arrive_dir": "down",
  "arrive_area": "exit_to_theporch",
  "arrive_sequence": [
    { "action": "narrate", "text": "HE STEPPED INSIDE...", "strict": true },
    { "action": "move", "actor": "character", "to": [320, 400], "strict": true }
  ]
}
```

### 6.3 Things

Each key in `"things"` must exactly match a thing node name in the `.tscn`.

```json
"things": {
  "door": {
    "look": [ ... ],
    "use":  [ ... ],
    "talk": [ ... ]
  },
  "axe": {
    "use": [
      { "action": "think", "actor": "character", "text": "THIS MAY BE USEFUL." },
      { "action": "add_to_inventory" },
      { "action": "set_flag", "name": "axeTaken", "value": "true" }
    ]
  }
}
```

Supported verbs: `look`, `use`, `talk`. Each is an array of event action objects. If a verb is absent for a thing, the framework uses the global fallback strings defined in `GameData.cs`.

### 6.4 Event Actions

Every action is a JSON object with an `"action"` field. Actions execute in order, one at a time. By default, each action suspends player input while it runs. `"strict": true` on `move` makes it non-interruptable (the character cannot be redirected mid-walk).

---

#### `move`
Walk a character or NPC to a position.

```json
{ "action": "move", "actor": "character", "to": [320, 400], "strict": true }
```

| Field | Description |
|---|---|
| `actor` | `"character"`, `"self"` (the thing being interacted with), or any NPC node name |
| `to` | `[x, y]` world-space coordinates |
| `target` | Thing node name — walks to that thing's `interactPoint` instead of `to` |
| `to_area` | `CollisionShape2D` node name — walks to the center of that exit/area shape |
| `strict` | `true` = non-interruptable walk; `false` (default) = player can interrupt |

Use exactly one of `to`, `target`, or `to_area`.

---

#### `narrate`
Display a narration box (no character tail).

```json
{ "action": "narrate", "text": "THE HOUSE WAS VERY QUIET." }
```

---

#### `speak`
Display a speech bubble above a character.

```json
{ "action": "speak", "actor": "character", "text": "HELLO THERE." }
```

---

#### `think`
Display a thought bubble above a character.

```json
{ "action": "think", "actor": "character", "text": "I WONDER WHAT THAT IS." }
```

---

#### `change_facing`
Instantly change which direction a character faces.

```json
{ "action": "change_facing", "actor": "character", "direction": "left" }
```

`direction`: `"up"`, `"down"`, `"left"`, or `"right"`

---

#### `look_at`
Face one actor toward a thing's position.

```json
{ "action": "look_at", "actor": "character", "target": "door" }
```

---

#### `play_animation`
Play a named animation on a thing's AnimationPlayer.

```json
{ "action": "play_animation", "actor": "door", "animation": "open" }
```

`actor` resolves as a thing node name (not an NPC). The thing must have an AnimationPlayer child.

---

#### `set_flag`
Create or update a scene flag. Flags persist across scene changes for the session.

```json
{ "action": "set_flag", "name": "porchDoorOpen", "value": "true" }
```

`value`: `"true"`, `"false"`, or any string. Boolean strings are converted to `bool`.

---

#### `branch_on_flag`
Evaluate a flag at execution time and run one of two sub-sequences.

```json
{
  "action": "branch_on_flag",
  "name": "porchDoorOpen",
  "is": false,
  "then": [
    { "action": "play_animation", "actor": "door", "animation": "open" },
    { "action": "set_flag", "name": "porchDoorOpen", "value": "true" }
  ],
  "else": [
    { "action": "speak", "actor": "character", "text": "IT'S ALREADY OPEN." }
  ]
}
```

`is`: the expected value of the flag (`true` or `false`). `then` runs if the flag matches; `else` runs otherwise. `else` is optional.

**Note:** `branch_on_flag` is evaluated at the moment it is reached in the queue — it reads the live flag value at that instant, not when the sequence was built.

---

#### `add_to_inventory`
Add the interacted thing to the player's inventory. Uses the thing node's `inventoryItemType` export value.

```json
{ "action": "add_to_inventory" }
```

No fields. Only valid in a thing's interaction sequence (`self` must be defined).

---

#### `wait`
Pause the event sequence for a number of seconds.

```json
{ "action": "wait", "seconds": 1.5 }
```

---

#### `remap_floor`
Replace the walkable navigation polygon with a different polygon from the scene. Used for state changes like opening a door that expands the walkable area.

```json
{ "action": "remap_floor", "polygon": "openDoorFloor" }
```

| Field | Description |
|---|---|
| `polygon` | Name of a **Polygon2D** child inside the NavigationRegion2D node. Its polygon replaces the active nav polygon. |
| `nav_region` | Node name of the NavigationRegion2D (default: `"NavigationRegion2D"`) |

To use `remap_floor`, add a **Polygon2D** child to the scene's `NavigationRegion2D` node with the alternate walkable shape. Name it something descriptive (e.g. `openDoorFloor`). It stays invisible at runtime — only its polygon data is used.

---

### 6.5 Resolving actors

In any action that takes an `actor` string:
- `"character"` → the player character
- `"self"` → the thing node whose interaction triggered the sequence
- Any other string → a node found by name in the scene (for NPCs or secondary things)

---

### 6.6 Complete JSON example

```json
{
  "exits": {
    "exit_to_kitchen": {
      "destination": "kitchen",
      "arrive_dir": "down"
    },
    "exit_to_hallway": {
      "destination": "hallway",
      "arrive_dir": "right",
      "no_walk": true
    }
  },
  "things": {
    "lamp": {
      "look": [
        { "action": "speak", "actor": "character", "text": "AN OLD OIL LAMP." }
      ],
      "use": [
        {
          "action": "branch_on_flag",
          "name": "lampLit",
          "is": false,
          "then": [
            { "action": "move", "actor": "character", "target": "lamp", "strict": true },
            { "action": "play_animation", "actor": "lamp", "animation": "light" },
            { "action": "set_flag", "name": "lampLit", "value": "true" },
            { "action": "speak", "actor": "character", "text": "THERE WE GO." }
          ],
          "else": [
            { "action": "speak", "actor": "character", "text": "IT'S ALREADY LIT." }
          ]
        }
      ]
    },
    "book": {
      "use": [
        { "action": "think", "actor": "character", "text": "MIGHT NEED THIS." },
        { "action": "add_to_inventory" },
        { "action": "set_flag", "name": "bookTaken", "value": "true" }
      ]
    }
  },
  "default": {}
}
```

## 7. Registering the Scene in GameData.cs

Open `game/GameData.cs` and make two additions:

### 7.1 Add a constant

```csharp
public const string YOURSCENE = "res://game/scenes/yourscene/yourscene.tscn";
```

Add this line inside the `Scenes` class alongside the other constants.

### 7.2 Add to the name lookup dictionary

```csharp
{ "yourscene", YOURSCENE },
```

Add this entry to the `_byName` dictionary in `Scenes`. The key must be lowercase and must match the `displayName` you set on the scene root node.

Once registered, use `Scenes.YOURSCENE` or `Scenes.Resolve("yourscene")` anywhere in C# to reference the scene path.

## 8. Adding a New Inventory Item (if needed)

If the new scene introduces a pick-up item that isn't already in `InventoryItem.ItemType`, add it:

```csharp
public enum ItemType
{
    none   = 0,
    key    = 1,
    candle = 2,
    bell   = 3,
    book   = 4,
    axe    = 5,
    youritem = 6,   // ← add here with the next integer
}
```

Then set `inventoryItemType = InventoryItem.ItemType.youritem` on the thing node in the editor.

## 9. Optional: Custom C# Logic

If JSON actions are not sufficient (e.g. complex state machines, procedural generation, dynamic NPC behaviour), create a C# scene script:

```csharp
// game/scenes/yourscene/yourscene.cs
public partial class yourscene : scene_script
{
    public override void _Ready()
    {
        base._Ready();
        // Restore state from flags, connect signals, etc.
    }
}
```

Attach this script to the scene root node instead of `scene_script.cs` directly.

For thing-specific custom logic, create a script extending `thing`:

```csharp
public partial class yourthing : thing
{
    public override void SpecificLook()
    {
        parentScene.eventQueue.AddEventSpeak(parentScene.character, "IT LOOKS IMPORTANT.");
    }

    public override void SpecificUse()
    {
        // Custom use logic
    }

    public override void SpecificUseItem(InventoryItem item)
    {
        if (item.Type == InventoryItem.ItemType.key)
        {
            // Respond to being used with the key
        }
    }
}
```

Overridable methods on `thing`:
- `SpecificLook()` — called when player looks at the thing
- `SpecificUse()` — called when player uses the thing
- `SpecificTalk()` — called when player talks to the thing
- `SpecificUseItem(InventoryItem item)` — called when player uses an inventory item on the thing

If a JSON interaction is defined for the same verb, the JSON takes precedence. To combine both, call `base.SpecificLook()` to trigger JSON, or avoid defining that verb in JSON and handle it entirely in C#.

## 10. Wiring Exits Between Scenes

For two scenes A and B to be connected:

1. **Scene A** has a `CollisionShape2D` named `exit_to_b`
2. **Scene A's JSON** has an `"exit_to_b"` entry with `"destination": "b"` and an `"arrive_dir"`
3. **Scene B** has a `CollisionShape2D` named `exit_to_a`
4. **Scene B's JSON** has an `"exit_to_a"` entry with `"destination": "a"` and an `"arrive_dir"`

The framework auto-detects which zone in B to place the character at by finding the exit whose `destination` matches A's `displayName`. No explicit `arrive_area` is needed when the connection is bidirectional.

Only add `arrive_area` when:
- The destination scene has no exit pointing back, OR
- You want to arrive at a specific zone that isn't the reverse exit (e.g. arriving through a different door than you left from)

## 11. Testing Checklist

Before considering a scene complete:

- [ ] Scene loads without errors (no "MainScene not found" or JSON parse errors in the output)
- [ ] Character spawns at a visible position and can walk freely within the navigation polygon
- [ ] All exits trigger scene transitions (character enters zone → transition fires)
- [ ] Character arrives at the correct position in the destination scene
- [ ] Auto-walk fires after the transition completes and respects the nav polygon
- [ ] All things are clickable and produce the correct responses
- [ ] `branch_on_flag` branches behave correctly before and after flags are set
- [ ] Pick-up items appear in inventory and can be removed from the scene
- [ ] `remap_floor` (if used) correctly expands the walkable area after the triggering action
- [ ] Shadows behave correctly under the scene light (if `castsShadow = true` things are present)
- [ ] Darkmap is sampled correctly (character and things darken in shadowed areas)
- [ ] Camera stays within the clamp region and doesn't show outside the background
- [ ] No scale anomalies — things scale with depth, frozen regions work as expected
